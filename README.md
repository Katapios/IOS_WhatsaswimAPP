# What's a Swim? - Приложение для отслеживания тренировок по плаванию

## Описание проекта

**What's a Swim?** — это комплексное приложение для отслеживания тренировок по плаванию, состоящее из двух компонентов:
- **Приложение для Apple Watch** — сбор данных с датчиков во время тренировки
- **Приложение для iPhone** — просмотр статистики и истории тренировок

## Архитектура приложения

### Компоненты

1. **WhatsaswimWatch** (watchOS приложение)
   - Сбор данных с датчиков
   - Определение стилей плавания
   - Отслеживание гребков и дистанции
   - Сохранение результатов тренировок

2. **Whatsaswim** (iOS приложение)
   - Календарь тренировок
   - Статистика по всем тренировкам
   - Детальная информация о каждой тренировке

### Синхронизация данных

Приложения синхронизируются через **App Group** (`ваш group`), используя `UserDefaults` с общим контейнером. Данные сохраняются в формате JSON и автоматически синхронизируются между устройствами.

## Логика работы приложения для Apple Watch

### 1. Главный экран (WatchContentView)

**Функционал:**
- Отображает кнопку "Поплыли!" для начала тренировки
- Показывает кнопку "Результаты", если сегодня была тренировка
- Автоматически проверяет наличие тренировки за сегодня при появлении

**Логика:**
- При запуске проверяет наличие тренировки через `TrainingResultsManager.shared.hasTrainingToday()`
- При получении уведомления `.trainingResultsSaved` обновляет состояние
- При нажатии на "Результаты" открывает экран с результатами сегодняшней тренировки

### 2. Экран тренировки (SwimTrainingView)

**Отображаемые данные:**
- Время тренировки (таймер)
- Температура воды
- Глубина погружения
- Дистанция
- Кнопки: "Пауза/Продолжить" и "Завершить"

**Логика работы:**

#### Запуск тренировки:
1. При появлении экрана (`onAppear`):
   - Запускается таймер для отсчета времени
   - Вызывается `sensorManager.startMonitoring()` для начала сбора данных с датчиков
   - Запускается сессия HealthKit для предотвращения блокировки экрана

#### Во время тренировки:
- Таймер отсчитывает время (останавливается при паузе)
- `SensorManager` собирает данные с датчиков:
  - Акселерометр — для определения гребков и стилей плавания
  - Device Motion — для определения глубины
  - HealthKit — для получения пульса и температуры
- Данные обновляются в реальном времени на экране

#### Пауза:
- При нажатии "Пауза":
  - Таймер останавливается (время не увеличивается)
  - Вызывается `sensorManager.pauseMonitoring()`:
    - Останавливается сбор данных с датчиков
    - Сессия HealthKit приостанавливается (но остается активной, экран не гаснет)
- При нажатии "Продолжить":
  - Таймер возобновляется
  - Вызывается `sensorManager.resumeMonitoring()`:
    - Возобновляется сбор данных
    - Сессия HealthKit возобновляется

#### Завершение тренировки:
1. При нажатии "Завершить":
   - Останавливается таймер
   - Генерируются результаты через `generateResults()`
   - Результаты сохраняются через `TrainingResultsManager.shared.saveResults()`
   - Отправляется уведомление `.trainingResultsSaved`
   - Останавливается мониторинг датчиков
   - Сбрасываются данные сенсора
   - Открывается экран с результатами

**Важно:** При закрытии экрана (`onDisappear`) мониторинг НЕ останавливается, чтобы данные не потерялись. Мониторинг останавливается только при явном завершении тренировки.

### 3. SensorManager — Менеджер датчиков

**Основные функции:**

#### Инициализация и авторизация:
- При первом запуске запрашивает авторизацию HealthKit
- Проверяет доступность датчиков (акселерометр, Device Motion)
- Создает сессию HealthKit для предотвращения блокировки экрана

#### Сбор данных:

**1. Определение гребков (`detectStroke`):**
- Анализирует данные акселерометра
- Определяет гребок по изменению ускорения (порог: 2.0)
- Фильтрует слишком частые гребки (минимум 0.5 секунды между гребками)
- Обновляет счетчик гребков
- Добавляет гребок к текущему сегменту стиля

**2. Определение стиля плавания (`detectSwimStyle`):**
- Анализирует паттерны движения:
  - Вертикальные движения (Y-ось)
  - Горизонтальные движения (X-ось)
  - Частота гребков за последние 5 секунд
- Определяет стиль по алгоритму:
  - **Баттерфляй**: сильные вертикальные движения (>2.0), высокая частота (>0.7), низкие горизонтальные (<1.5)
  - **Кроль**: быстрые горизонтальные (>1.5), высокая частота (>0.8), низкие вертикальные (<1.3)
  - **На спине**: умеренные горизонтальные (1.0-1.5), средняя частота (0.5-0.8), низкие вертикальные (<1.0)
  - **Брасс**: симметричные движения (разница <0.25), низкая частота (0.15-0.5), средняя величина (1.0-1.7)
- Использует окно уверенности 5 секунд для стабильного определения
- Минимум 3 секунды для смены стиля (чтобы избежать ложных переключений)

**3. Отслеживание остановок движения:**
- Таймер проверяет каждую секунду наличие гребков
- Если прошло более 5 секунд без гребков — фиксируется остановка
- При остановке:
  - Записывается текущий сегмент 25м с количеством гребков
  - Сбрасывается счетчик гребков для нового сегмента
  - Устанавливается флаг `isStopped = true`
- При возобновлении движения:
  - Определяется стиль (может быть новый)
  - Начинается новый подсчет гребков
  - Сбрасывается флаг остановки

**4. Запись сегментов 25м:**
- Каждый раз при остановке движения (более 5 секунд) записывается сегмент 25м
- Сегмент содержит:
  - Количество гребков на этом отрезке
  - Стиль плавания
- Сегменты сохраняются в массиве `strokesPer25m` для каждого стиля

**5. Вычисление дистанции:**
- Дистанция вычисляется на основе количества гребков и стиля
- Средняя длина гребка по стилям:
  - Баттерфляй: 1.5 м
  - Кроль: 2.0 м
  - На спине: 1.8 м
  - Брасс: 1.2 м
- Общая дистанция = сумма дистанций всех сегментов

**6. Мониторинг других показателей:**
- **Пульс**: через HealthKit (если доступен)
- **Температура воды**: через HealthKit (температура тела) или значение по умолчанию (26°C)
- **Глубина**: через Device Motion (анализ ускорения по Z-оси)

#### Сессия HealthKit:
- Запускается при начале тренировки
- Предотвращает блокировку экрана во время тренировки
- Остается активной при паузе (экран не гаснет)
- Завершается только при окончании тренировки

### 4. TrainingResultsManager — Менеджер результатов

**Функции:**
- Сохранение результатов в App Group
- Загрузка результатов за сегодня
- Загрузка всех результатов
- Проверка наличия тренировки за сегодня

**Логика сохранения:**
1. При сохранении результатов:
   - Загружаются все существующие результаты
   - Проверяется наличие результатов за сегодня
   - Если есть — заменяются новыми (на случай повторного завершения)
   - Если нет — добавляются новые
   - Результаты сортируются по дате (новые сначала)
   - Сохраняются в JSON формате в App Group
   - Отправляется уведомление `.trainingResultsSaved`

**Структура данных:**
```swift
struct SwimResults {
    let duration: TimeInterval      // Длительность тренировки
    let distance: Double            // Общая дистанция
    let waterTemperature: Double   // Температура воды
    let averageDepth: Double       // Средняя глубина
    let styles: [SwimStyle]       // Массив стилей
}

struct SwimStyle {
    let name: String              // Название стиля
    let totalStrokes: Int        // Всего гребков
    let segments25m: [Int]       // Гребки на каждый отрезок 25м
}
```

### 5. Экран результатов (SwimResultsView)

**Отображает:**
- Длительность и дистанцию
- Список всех стилей с количеством гребков
- Сегменты по 25м для каждого стиля
- Дополнительную информацию (температура, глубина, скорость, всего гребков)

## Логика работы приложения для iPhone

### 1. Главный экран (ContentView)

**Структура:**
- TabView с двумя вкладками:
  - **Календарь** — просмотр тренировок по датам
  - **Статистика** — общая статистика по всем тренировкам

### 2. Календарь тренировок (CalendarView)

**Функционал:**
- Отображение календаря с датами
- Выделение дат с тренировками (синяя точка)
- Кликабельность только дат с тренировками
- Навигация по месяцам
- Кнопка обновления данных

**Логика работы:**

#### Отображение календаря:
1. При загрузке:
   - Загружаются все результаты через `TrainingDataManager`
   - Извлекаются даты с тренировками
   - Формируется сетка календаря (42 дня = 6 недель)
   - Выделяются даты с тренировками

2. При клике на дату:
   - Проверяется наличие тренировки на эту дату
   - Если есть — открывается модальное окно с детальной информацией
   - Если нет — ничего не происходит

3. Обновление данных:
   - При получении уведомления `.trainingResultsSaved` обновляется календарь
   - При смене месяца обновляются данные
   - Кнопка обновления принудительно синхронизирует данные

#### Детальный просмотр тренировки (TrainingDetailView):
- Отображает полную информацию о тренировке:
  - Дата и время тренировки
  - Длительность и дистанция
  - Все стили плавания с детальной информацией
  - Гребки на каждый отрезок 25м
  - Дополнительные показатели (температура, глубина, скорость)
  - Распределение по стилям

### 3. Статистика (StatisticsView)

**Отображаемые данные:**

#### Общая статистика:
- Всего тренировок
- Общее время тренировок
- Общая дистанция
- Всего гребков

#### Статистика по стилям:
- Для каждого стиля:
  - Количество использований
  - Всего гребков
  - Общая дистанция

#### Последние тренировки:
- Список последних 5 тренировок
- Дата, время, длительность, дистанция

**Логика:**
- При загрузке загружаются все результаты
- Вычисляется статистика по стилям
- Отображаются последние тренировки
- Pull-to-refresh обновляет данные
- При получении уведомления `.trainingResultsSaved` обновляется статистика

### 4. TrainingDataManager — Менеджер данных для iPhone

**Функции:**
- Загрузка данных из App Group
- Управление датами тренировок
- Получение результатов для конкретной даты
- Обновление данных

**Логика:**
- Использует тот же App Group, что и приложение для часов
- При инициализации загружает даты тренировок
- Метод `refresh()` принудительно синхронизирует данные
- Все операции с датами используют `startOfDay` для точного сравнения

## Технические детали

### Используемые технологии:
- **SwiftUI** — UI фреймворк
- **HealthKit** — для данных о здоровье и сессий тренировок
- **CoreMotion** — для работы с датчиками движения
- **UserDefaults + App Group** — для синхронизации данных
- **NotificationCenter** — для уведомлений между компонентами

### Структура данных:

**SwimResults:**
- `duration`: Длительность тренировки в секундах
- `distance`: Общая дистанция в метрах
- `waterTemperature`: Температура воды в градусах Цельсия
- `averageDepth`: Средняя глубина в метрах
- `styles`: Массив стилей плавания

**SwimStyle:**
- `name`: Название стиля ("Кроль", "Баттерфляй", "Брасс", "На спине", "Не определен")
- `totalStrokes`: Общее количество гребков для этого стиля
- `segments25m`: Массив с количеством гребков на каждый отрезок 25м

**SavedTrainingResult:**
- `date`: Дата и время тренировки
- `results`: Объект SwimResults

### Алгоритм определения стилей:

1. **Сбор данных:** Анализируются данные акселерометра каждые 0.1 секунды
2. **Вычисление параметров:**
   - Вертикальное движение (abs(Y))
   - Горизонтальное движение (abs(X))
   - Частота гребков (количество за 5 секунд)
   - Общая величина ускорения
3. **Определение стиля:** Сравнение параметров с пороговыми значениями
4. **Стабилизация:** Использование окна уверенности 5 секунд
5. **Смена стиля:** Минимум 3 секунды для подтверждения смены

### Алгоритм записи сегментов 25м:

1. **Подсчет гребков:** Каждый гребок увеличивает счетчик `currentSegmentStrokes`
2. **Отслеживание остановок:** Таймер проверяет каждую секунду наличие гребков
3. **Обнаружение остановки:** Если прошло более 5 секунд без гребков
4. **Запись сегмента:** Количество гребков записывается в `strokesPer25m` текущего стиля
5. **Сброс счетчика:** Начинается новый подсчет для следующего сегмента

### Синхронизация через App Group:

1. **На часах:**
   - Результаты сохраняются в `UserDefaults(suiteName: "group.KP")`
   - Ключ: `"savedTrainingResults"`
   - Формат: JSON массив `[SavedTrainingResult]`
   - Принудительная синхронизация через `synchronize()`

2. **На iPhone:**
   - Те же `UserDefaults` и ключ
   - Автоматическое обновление при получении уведомления
   - Принудительная синхронизация при обновлении

3. **Уведомления:**
   - При сохранении отправляется `NotificationCenter.default.post(name: .trainingResultsSaved)`
   - Оба приложения подписаны на это уведомление
   - При получении обновляются данные

## Особенности реализации

### Предотвращение блокировки экрана:
- Используется `HKWorkoutSession` с типом `.swimming`
- Сессия запускается при начале тренировки
- Остается активной при паузе
- Завершается только при окончании тренировки

### Обработка паузы:
- При паузе сессия HealthKit приостанавливается, но не завершается
- Это позволяет экрану оставаться активным
- При возобновлении сессия продолжается

### Обработка остановок движения:
- Таймер проверяет наличие гребков каждую секунду
- Порог остановки: 5 секунд без гребков
- При остановке записывается сегмент 25м
- После остановки может измениться стиль

### Обработка данных:
- Все обновления UI происходят на главном потоке
- Операции с датчиками выполняются в фоновых потоках
- Синхронизация через `DispatchQueue.main.async`

### Обработка ошибок:
- Проверка доступности датчиков
- Fallback на стандартный UserDefaults, если App Group недоступен
- Обработка случаев, когда стиль не определен
- Обработка пустых результатов

## Заключение

Приложение обеспечивает полный цикл отслеживания тренировок по плаванию:
- Сбор данных с датчиков в реальном времени
- Автоматическое определение стилей плавания
- Точная запись гребков на каждый отрезок 25м
- Синхронизация данных между устройствами
- Удобный просмотр статистики и истории

Все данные сохраняются локально и синхронизируются через App Group, обеспечивая надежную работу без зависимости от интернета.
